## Breve síntesis del sistema

**Bartender System** es una plataforma destinada a bares y restaurantes que busca centralizar y digitalizar diferentes procesos del establecimiento dentro de un mismo ecosistema.

El sistema contempla diferentes tipos de usuarios y áreas de trabajo, entre ellas:

* Clientes.
* Bartenders.
* Mozos/camareros.
* Cocina.
* Caja.
* Administración.

Desde el lado del cliente, el sistema permitirá consultar la carta, visualizar productos y promociones, realizar pedidos, gestionar el carrito y realizar reservas.

Desde el lado interno del establecimiento, permitirá gestionar productos, recetas, inventario, pedidos, reservas, operaciones y diferentes aspectos administrativos.

La principal utilidad del sistema es **reducir la dependencia de procesos manuales y centralizar la información**, permitiendo que diferentes sectores del establecimiento trabajen sobre una misma plataforma.

El proyecto busca además ofrecer una experiencia moderna, intuitiva y adaptable tanto a dispositivos móviles como a computadoras.

# Libro de marca y diseño de interfaz

Este será uno de los puntos principales del desarrollo del proyecto.

El **Libro de Marca** establecerá la identidad visual de Bartender System y funcionará como guía para garantizar que todas las interfaces futuras mantengan una misma identidad, independientemente de si corresponden al cliente, bartender, administrador, cocina u otro usuario.

Para desarrollar y documentar la identidad visual se utilizará principalmente **Figma**, debido a que permite crear sistemas de diseño mediante componentes, estilos, variables y bibliotecas reutilizables. Estas características permiten mantener consistencia entre diferentes interfaces y facilitar posteriormente la implementación en código.

### Contenido previsto del Libro de Marca

El Libro de Marca estará compuesto por los siguientes apartados:

### 1. Identidad de marca

Se definirá:

* Nombre de la marca.
* Concepto de Bartender System.
* Personalidad de la marca.
* Valores.
* Público objetivo.
* Concepto visual.
* Posicionamiento.
* Tono general de comunicación.

La identidad buscará transmitir principalmente:

**Profesionalidad + tecnología + ambiente nocturno + gastronomía + eficiencia.**

La intención es evitar una estética genérica de software administrativo y desarrollar una identidad relacionada directamente con el mundo de los bares y restaurantes, pero manteniendo una apariencia tecnológica y profesional.

### 2. Logotipo

Se establecerán las reglas de utilización del logotipo:

* Logotipo principal.
* Versiones alternativas.
* Versión horizontal.
* Versión compacta.
* Uso sobre fondos claros.
* Uso sobre fondos oscuros.
* Área de protección.
* Tamaño mínimo.
* Usos incorrectos.

Esto permitirá que el logotipo conserve su identidad independientemente del lugar donde sea utilizado.

### 3. Paleta cromática

Se definirá una paleta principal y una paleta secundaria.

La propuesta visual estará basada principalmente en una **interfaz oscura**, combinando tonos neutros con colores de acento relacionados con el ambiente de un bar moderno.

La paleta deberá contemplar:

* Color primario.
* Color secundario.
* Color de acento.
* Background principal.
* Background secundario.
* Superficies.
* Bordes.
* Texto principal.
* Texto secundario.
* Estados de éxito.
* Estados de advertencia.
* Estados de error.
* Estados informativos.

Los colores no solamente tendrán una función estética, sino también funcional. Se buscará que exista suficiente contraste y que los estados no dependan exclusivamente del color para comunicar información. Esto coincide con las recomendaciones actuales de diseño de sistemas de Figma sobre accesibilidad y uso funcional del color.

### 4. Tipografía

Se establecerá una familia tipográfica principal y sus diferentes usos.

Se documentarán:

* Familia tipográfica.
* Títulos.
* Subtítulos.
* Texto principal.
* Texto secundario.
* Labels.
* Botones.
* Números.
* Precios.
* Estados.
* Jerarquías.
* Tamaños.
* Pesos.
* Interlineado.

La tipografía deberá mantener una estética moderna y tecnológica, pero priorizando la legibilidad.

### 5. Iconografía

Se establecerá un sistema de iconos consistente para todo el producto.

Se definirán:

* Estilo de iconos.
* Tamaños.
* Grosor.
* Espaciado.
* Estados.
* Iconos de navegación.
* Iconos de acciones.
* Iconos de estados.

La utilización de un sistema consistente evitará que cada sección de la aplicación utilice iconos con estilos diferentes.

### 6. Componentes de interfaz

El Libro de Marca evolucionará hacia un **Design System** que contendrá componentes reutilizables.

Entre ellos:

* Botones.
* Inputs.
* Selectores.
* Cards.
* Modales.
* Dropdowns.
* Tabs.
* Badges.
* Alertas.
* Toasts.
* Tablas.
* Navegación.
* Sidebars.
* Headers.
* Menús.
* Formularios.
* Estados de carga.
* Estados vacíos.
* Estados de error.

Figma permite crear componentes reutilizables y bibliotecas compartidas para mantener estos elementos consistentes entre diferentes diseños.

### 7. Layout y sistema de espaciado

Se definirá un sistema de:

* Márgenes.
* Padding.
* Gaps.
* Radios.
* Tamaños de contenedores.
* Grillas.
* Breakpoints.
* Distribución de contenido.

Se priorizará un diseño **responsive y mobile-first**, teniendo en cuenta que el sistema tendrá diferentes experiencias según el dispositivo utilizado.

### 8. Diseño responsive

Se establecerán criterios para:

* Mobile.
* Tablet.
* Desktop.
* Pantallas grandes.

Los componentes deberán adaptarse sin perder jerarquía ni funcionalidad.

### 9. Estados e interacción

Se documentarán los estados de los componentes:

* Default.
* Hover.
* Focus.
* Active.
* Disabled.
* Loading.
* Success.
* Warning.
* Error.

Esto permitirá que la interfaz tenga un comportamiento visual consistente.

### 10. Experiencia de usuario

Además de la estética, el diseño buscará priorizar:

* Claridad.
* Rapidez de uso.
* Jerarquía visual.
* Accesibilidad.
* Facilidad de navegación.
* Consistencia.
* Reducción de pasos innecesarios.

El objetivo será que un usuario pueda utilizar el sistema sin necesidad de conocer previamente cómo funciona.

# Tiempo estimado de desarrollo

El tiempo estimado dependerá del alcance final del proyecto y de la cantidad de módulos que se implementen.

Como planificación inicial se estima un período aproximado de:

**12 a 16 semanas.**

Una posible distribución sería:

| Etapa                                   | Tiempo estimado |
| --------------------------------------- | --------------: |
| Investigación y definición del proyecto |        1 semana |
| Identidad visual y Libro de Marca       |       2 semanas |
| Sistema de diseño y prototipos          |       2 semanas |
| Arquitectura y desarrollo Backend       |     2-3 semanas |
| Desarrollo de interfaces                |     3-4 semanas |
| Integración y funcionalidades           |     1-2 semanas |
| Testing y correcciones                  |     1-2 semanas |

El **Libro de Marca y Design System** se desarrollarán en las primeras etapas para que posteriormente sirvan como referencia visual durante todo el desarrollo del software.

## Conclusión

El objetivo no será únicamente desarrollar un software funcional, sino construir una **marca digital y un sistema visual coherente** que pueda mantenerse a medida que Bartender System crezca.

El Libro de Marca será la base visual del proyecto y posteriormente se transformará en un Design System aplicable a las diferentes interfaces del ecosistema. De esta manera, cliente, bartender, administración, cocina y demás usuarios podrán utilizar interfaces diferentes pero pertenecientes a una misma identidad.
