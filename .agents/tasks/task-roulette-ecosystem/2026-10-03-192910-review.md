# Roulette Ecosystem Overhaul

The change delivers the full Roulette Ecosystem across four FEATs: a SpinPhase state machine that decouples result delivery from visual animation, a Web Audio API synthesizer, SVG visual upgrades on both desktop and web wheels, a mobile SVG wheel replacing a bare `View` placeholder, progressive haptics, backend jackpot socket emission, HMAC-signed Golden Ticket VIP, and two new desktop UI panels (JackpotBanner, WinnerCard). All four FEAT files show `status: "completed"` and both documentation files (`ROULETTE_PLAN.md`, `ROULETTE_MEMORIA.md`) exist at the worktree root. Watch for: the `pendingResult` closure in `onWheelLanded`, the `TICKET_SECRET` default in the backend, and the `@ts-ignore` on `AnimatedG` rotation in `MobileWheel`.

**Verdict**: APPROVED

---

## High-level view

The SpinPhase machine (`idle → launching → spinning → revealing → landing → revealed`) is fully implemented in `useRoulette.ts` and propagated through `RouletteWheelRoyale`, `RoulettePreview`, and `RoulettePage`. The `revealedResult` is only populated after `onWheelLanded` fires at the end of the 5-second wheel animation, so the winner is not visible to any observer before the animation completes — the spoiler problem is eliminated.

`useRouletteAudio.ts` creates a lazy `AudioContext` on first play and synthesises all sounds (ticks, impact, per-rarity fanfares) directly via Web Audio API nodes. No MP3 assets are referenced anywhere in the hook.

`RouletteWheelRoyale` adds 36 gold rivets at r=96, a double-ring `linearGradient` bezel, and 12 chase lights driven by a `requestAnimationFrame` loop during `spinning`/`revealing`. The wheel animation uses a rAF free-spin loop that hands off to a CSS transition (`cubic-bezier(0.15, 0.8, 0.3, 1)`) for the reveal — this avoids framer-motion spring conflicts with the rotation state.

The web `RouletteWheel.tsx` change is strictly a `WHEEL_COLORS` constant swap to the Obsidian palette. No logic, hooks, or module imports were touched.

`MobileWheel.tsx` renders a complete SVG pie chart via `react-native-svg` (`Svg`, `G`, `Path`, `Circle`, `Text`, `Polygon`) driven by `Animated.Value` through an `AnimatedG`. The old `circleOuter`/`circleInner` `View` placeholders are removed from `RouletteScreen.tsx`. Rotation is applied via SVG `transform` prop with a `@ts-ignore` because `AnimatedG`'s TypeScript bindings don't expose `origin`.

The backend `rouletteTicket.controller.js` uses `crypto.timingSafeEqual` for HMAC comparison with a length pre-check, which closes the timing-oracle and length-shortcut vulnerabilities. The default `TICKET_SECRET` is a hardcoded placeholder that will silently be used in production if the env var is not set — this is a known gap documented in the FEAT.

`JackpotBanner` has `position: "fixed"`, `top: 0`, `left: 0 / right: 0`, and `zIndex: 100`. It auto-closes via an 8-second `useEffect` timeout that cleans up on unmount and on `visible` change.

`WinnerCard` includes a `printPOSReceipt` function that injects a `@media print` style tag and a receipt `div` into the DOM, calls `window.print()`, then removes both elements after 100 ms.

<summary>Issues (2)</summary>

1. **`onWheelLanded` stale closure on `pendingResult`** — `onWheelLanded` captures `pendingResult` at the time of the `useCallback`. If the component re-renders between `revealing` and the `onLanded` callback firing (e.g. a concurrent drinks socket update), `pendingResult` may be stale at the moment it is moved to `revealedResult`. Fix: read `pendingResult` from a ref inside the callback, the same way `drinksRef` is used for `drinksRef.current` in the spin path.

2. **`TICKET_SECRET` default in production** — `const SECRET = process.env.TICKET_SECRET ?? 'bartender-ticket-secret'` silently falls through to a known public string if the env var is absent. Any operator who deploys without setting `TICKET_SECRET` will issue tickets that can be forged using the known default. The fallback should either throw at startup or require an explicit non-default value.

</details>

### SpinPhase machine eliminates the spoiler problem

`revealedResult` is `null` until `onWheelLanded` is called. `onWheelLanded` is wired to `RouletteWheelRoyale`'s `onLanded` prop, which fires via a 5100 ms `setTimeout` triggered at the start of the `revealing` phase transition in the wheel component. `WinnerCard` gates its content render on `phase === 'revealed' && drink`, so the winner name and stats are invisible to the DOM during `spinning` and `revealing`. The `lastResult` and `spinning` backward-compat aliases on the hook export preserve the shape consumed by `RouletteStats` and any other downstream consumers not yet migrated to `phase`.

There is a confirmed gap: `onWheelLanded` is declared with `useCallback([pendingResult])` (confirmed), meaning it captures `pendingResult` at the point it was last recreated. The 5100 ms timer in the wheel fires with the ref'd version of `onLanded` (`onLandedRef.current`), which ensures the latest callback is invoked — but the callback itself still closes over the `pendingResult` state value from when it was last re-created. If a socket-driven drinks update causes a re-render between `revealing` and the timer firing, and the re-render for some reason doesn't also re-create `onWheelLanded` with the new closure, the wrong value could land. The safe fix is to hold `pendingResult` in a `useRef` and read the ref inside the callback, matching the `drinksRef` pattern already in the hook. Confidence: **confirmed** (the closure dependency on `pendingResult` is visible in the `useCallback` declaration).

### HMAC ticket security

`redeemTicket` first checks `sigBuf.length !== expBuf.length` before calling `timingSafeEqual`, which correctly prevents a panic on mismatched buffer sizes. The JSON serialisation used for signing (`JSON.stringify(payload)`) is deterministic only if the property insertion order of `parsed` after destructuring `sig` matches the order used at `generateTicket` time. In V8 this holds for string keys in insertion order, but it is a hidden invariant worth documenting. The `TICKET_SECRET` default issue is the actionable concern (see Issues list). Confidence: **confirmed**.

### Test coverage

No new test files are included in this diff. The ticket controller's HMAC logic and the `onWheelLanded` state transition are the two paths most likely to surface bugs in production that unit tests would catch. The `timingSafeEqual` length pre-check and the spoiler-prevention gating are not covered by any automated assertion.
